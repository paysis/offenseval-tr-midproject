With 750 labelled tweets, does fine‑tuning beat a calibrated open LLM?

Research question · unchanged · formal test: the two proposal LLMs

Why these counts matter

Only 19.3% of training tweets are offensive. A model that only answers “not offensive” looks right at first glance: 80.7% accuracy. Its macro-F1 is 0.447, though, so accuracy alone hides the failure. What explains the gap
  • It is not the tokenizer. Gemma packs these tweets more tightly: 32.3 vs 37.9 tokens/tweet.
  • Qwen is shifted, not blind. At threshold 0 it calls 99% of tweets offensive, but the ranking still works: best-threshold F1 is 0.677.
  • Gemma is already centred. F1 at 0 is 0.763 and the best threshold reaches 0.765, so threshold tuning has almost nothing to gain here.
  • Oracle, diagnostic only. F1 @ best picks the threshold on dev itself, so it is an upper bound, not a result; no setting is chosen from it.
This is threshold geometry, not proof of contamination. It does not separate pretraining language from alignment; the exact-completion check is still planned.

Title, abstract, research question, contributions

1 · Title and abstract

Fine-tuning BERTurk vs threshold-calibrated open LLMs for Turkish offensive language with 750 labels.

Small Turkish platforms can label only a few hundred tweets. We ask a narrow question: with 750 labelled OffensEval-TR tweets, does a fine-tuned BERTurk beat an open LLM that gets the same 750 labels as 8 prompt examples and 742 calibration tweets for its decision threshold? The TF-IDF + logistic-regression baseline scores 0.763 macro-F1 on the frozen 3,528-tweet test set, but only 0.620 with 750 labels. The LLM arm scores each tweet as log P(A) − log P(B), and the 742 labels set its threshold. On dev, calibration moves Qwen3-8B from 0.162 to 0.628 and Gemma-2-9B from 0.412 to 0.500; Qwen3-14B reaches 0.773 (zero-shot 0.171) and Gemma-4-12B 0.790 ± 0.007 (zero-shot 0.763). Fine-tuned BERTurk reaches 0.767 ± 0.014 on dev with 750 labels. Gap: the frozen-test comparison is pending; the final result uses the paired bootstrap.

2 · Research question

Unchanged. With 750 labels, does fine-tuning BERTurk beat prompting Gemma-2-9B-it or Qwen3-8B (same 750 tweets, 8 examples plus 742 threshold labels) on macro-F1 over the official 3,528-tweet test set?

“No” result: BERTurk’s mean over 10 runs is not ≥0.02 above the LLM’s mean over 3 runs, or the paired bootstrap says chance (p ≥ 0.05). Change: Qwen3-14B and Gemma-4-12B were added after the first dev results; the formal test (0.02 gap, paired bootstrap) uses only Gemma-2-9B and Qwen3-8B, and the new models are extra analysis. Compute: paid Colab Pro L4 instead of free T4.

3 · Contributions

C1. At 750 labels, we test whether BERTurk’s mean test macro-F1 is ≥0.02 above each LLM’s, and whether a paired bootstrap rejects chance. Test pending; on dev BERTurk 0.767 vs 0.628 / 0.500.

C2. The 742-label threshold improves each LLM’s dev macro-F1 over zero-shot; we report per-model delta and spread.

C3. The learning curve tests how many labels fine-tuning needs to overtake the best calibrated LLM; on dev BERTurk passes Gemma-4-12B (0.790) between 750 and 2,000 labels (0.767 to 0.793). If the lines never cross on test, the 750-label answer stands.

Method, protocol, results so far, error analysis

6 · Method and baseline

TF-IDF word 1-2 + char_wb 2-5, min_df=2, sublinear, Turkish lowercasing; LR C=1.0, balanced. Test 0.763 [0.745, 0.779].

Fine-tuning: BERTurk/XLM-R, 128 tokens, batch 16, 2e-5, 4 epochs or 400 updates, class-weighted, no early stopping. LLM: Qwen/Gemma 4-bit, 8 examples, 742-label threshold. One change: labels train weights vs choose examples and threshold.

Compute used: about 3 Colab units for the 46 fine-tuning runs + 2.5 L4-h for 16 LLM passes; about 18 GPU-h needed for the final. Change: paid Colab Pro L4 instead of the proposal’s free T4, for speed.

7 · Evaluation protocol

Macro-F1; frozen 3,528-tweet test; 10 BERTurk runs at 250/750/2,000 and 3 at 6,000/30,000; 3 runs per LLM at 750. Paired bootstrap, 10,000 resamples; real gap ≥0.02 and wins on ≥95%. Fixed before method results; dev for code checks only.
